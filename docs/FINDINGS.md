## 运维

### 上传到已有目录不会「替换」它 —— 同名文件按时间戳覆盖，多余文件原样保留

`blob_manager` 的 `upload` 与备份脚本都用 `--overwrite ifSourceNewer`（不是 azcopy 默认的 `true`）。实测三条行为：

- **同名文件**：只有本地 mtime **严格更新**才覆盖，否则静默跳过；
- **目标里多出来、本地没有的文件**：**不删**，原样留着 —— 上传是「合并叠加」，不是「镜像替换」；
- **本地改了内容但 mtime 没变新**（`cp -p`、`git checkout`、解压保留时间戳）→ **静默跳过**，远程还是旧内容。实测改了内容+回设 2020 年时间戳，远程仍是旧版本。

更细的一条：blob 的 Last-Modified 是**秒级**粒度，实测本地文件比远程新 1 毫秒仍被判为「不更新」而跳过。

**为什么重要**：两个方向都会咬人。想「用新版覆盖旧目录」→ 可能因时间戳没推进而**什么都没传**，看日志是 Skipped 不是错误；想「清掉旧文件」→ 上传永远做不到，必须显式 `rm`。这也意味着**备份同样漏掉 mtime 不推进的文件**。

📄 `CHANGELOG.md` 2026-08-25 `[运维]` 覆盖语义条

### 配了 3 天的自动备份一次都没成功过，而日志看起来一切正常

8-23 建立的 blob 自动备份，到 8-25 共跑了 86 轮，**成功次数为 0**，远程目录是空的。原因是 `blob_manager.py` 把 SAS token **烤进**它生成的备份脚本，而当时取到的是代码里那个 2026-04-05 就过期的默认 token —— 每个文件都 403，但日志照常一轮轮滚动。

**为什么重要**：**一个从未生效的备份比没有备份更危险**，它提供虚假的安全感。故障模式是「静默降级 + 日志照常」，靠瞥一眼日志发现不了，得去数成功次数或看远程有没有东西。

由此定下两条做法：凭证**每轮现读配置文件**、不缓存不烤死；状态输出必须**区分「部分成功」与「整轮失败」**，并在全轮失败时显式报警。

📄 `CHANGELOG.md` 2026-08-25 `[运维]` `[修正]` 条

### Azure Blob 没有改名，「改名」是复制 + 删除 —— 于是删除权限决定了方案形态

想让备份目录名跟随日期（`nyp_0825`），就得给 58G 的目录改名；而 blob 是扁平存储，改名 = 服务端复制一份 + 删掉旧的。当前 SAS token 是 `sp=racwl`，**没有 `d`**，删不掉。

**为什么重要**：这不是「先凑合上线、以后补权限」的小事 —— 若照常改名，旧目录删不掉，会在**多人共用**的容器里**每天多堆一份 58G**。所以选择了「探测不到删除权限就跳过改名、继续同步到旧目录并告警」，宁可目录名滞后也不制造垃圾。权限补上后自动恢复。

顺带两个 azcopy 的实测语义（都会静默产生错误结构，不会报错）：目录拷贝**会把源目录名多套一层**，要平移内容必须用 `src/*`；而该通配**包含** `.git` 这类隐藏项（与 bash 的 `*` 行为相反）。

📄 `scripts/blob_backup.sh` 头部注释；待办见 `USER_ACTIONS.md` M-009 / M-010

## 方法论

### 坡度是角度，角度在缩放下不变 —— C2 的核心量根本不需要 LiDAR

我曾在设计文档里写「坡度、粗糙度由 LiDAR 确定性计算（强监督）」。这是错的。**坡度是角度，均匀缩放不改变角度**；粗糙度取「残差 RMS 与局部尺寸之比」后同样消掉尺度。视觉点云即便尺度完全未知，依然给出正确的坡度和平整度比值。

**为什么重要**：这一条直接把「安全降落区评估」从「需要 LiDAR 的特殊能力」变回「任何低空数据集都能做」。更一般的规律是：**视觉深度的误差以尺度和低频偏置为主**，所以序数（谁更高）、共面性、角度、比值这些量**天然免疫**，而「多少米」被摧毁。

把目标从「多少米」改成「哪个更高/更平/是否共面」，误差的主要成分被直接消掉，**而在近垂直下视里这些量仍然没有外观对应物** —— 3D 必要性一点没降。这是本项目最重要的设计杠杆。

📄 `DESIGN.md` §40.5 机制 2、§46.2

### 对可信度任务来说，教师犯错不是噪声，是数据

用模型提取的 3D metadata 去造训练数据，通常的顾虑是「教师错了，学生就学错」。但对「感知可信度」这一类能力，**你要学生学的正是「视觉三维在哪里会失效」** —— 教师的失效模式本身就是标注来源。

**为什么重要**：这解释了为什么 C1 应该是纯视觉管线的旗舰能力，而不是被 LiDAR 缺失卡住的能力。而且失效标注可以完全不用真值：扰动法（调暗/模糊/抽视角后看几何漂移多少）、分歧法（多个估计器打架的地方）、自洽违反（重投影/环路误差大的地方）——三条路都是可复算的测量，不是模型的观点。

顺带：我做的日/暮实验其实就是扰动法的一次完整演示，全程没用 LiDAR。当时却把它写成「需要外参才能定量」，属于被错误框架带偏了。

📄 `DESIGN.md` §40.5 机制 4、§52.1

## 3D 增益（R-43，铁律 5 的准入线）

### 打乱 metadata 比不给 metadata 还差 —— 这才是「模型真在用它」的证据

首次三档消融（14 条真实样本 × 3 次，Qwen3.5-35B-A3B）：

| | 2D-only | 2D+metadata | **打乱 metadata** |
|---|---:|---:|---:|
| Grounding（序数「最远」） | 0.286 | **0.571** | **0.143** |
| 方位（排除歧义样本） | 1.000 | 1.000 | 0.167 |

**为什么重要**：只比「给 metadata」vs「不给」是不够的 —— b 高于 a 也可能只是
「多给几个 token 就涨分」。真正说明问题的是 **c 掉到 a 以下**：
喂错误几何时模型答得**比什么都不给还差**，说明它确实在读几何并据以推理。
这是 §29.2 设计 arm c 的全部理由，实测证明它抓得住东西。

⚠ **样本量 14 条，远不够 §29.1 的准入判定。** 这一轮只证明**测量管线通了**。

📄 `CHANGELOG.md` 2026-08-25；明细 `metadata/lift_results.json`

### 近垂直下视让「前后」方位题退化了

方位任务问「目标在观察者的前后 / 左右」。但 nadir 相机朝下，**几乎所有实体都在「前方」**，
longitudinal 分量恒为 front，题目实际退化成左右二选一。实测 2D-only 在非歧义样本上
拿到 6/6 —— 不是模型强，是题目太好猜。

另有 6/7 条方位样本落在**横向死区**（±10°）被 checker 判为不合格。
死区判负是设计如此（那里左右会因位姿微小误差翻转，没有稳定真值），
但这意味着**该任务在本数据集上的有效样本率只有 ~14%**。

**为什么重要**：这不是实现 bug，是**任务与数据几何的错配**。
要么换成对 nadir 有意义的方位形态（如方位角分档、相对北向），要么承认它在航测数据上价值有限。
grounding 那条序数题没有这个问题 —— 它测的是深度序关系，恰恰是 nadir 下最缺的信息。

📄 `DESIGN.md` §52 的 C3-a 论证

### 尺度无关任务里混进米制常数，会静默毁掉整批样本

三处实测踩到的：Task Spec 要求 `scale_status: metric`、`camera_baseline_m_at_least: 2.0`、
`domain_calibrated: true`；推导程序里写死「最远与次远差距不足 **1 m** 判为歧义」。

这些都是「强制 metric」时期的遗留。可 grounding 的「最远」是**序数**、方位是**角度**、
跨视角同一性是**布尔** —— 三者在均匀缩放下都不变，本就不需要米制。

后果分两种，**第二种更危险**：前三条让 relative 场景**全部失去资格**（有报错，看得见）；
最后一条在 VGGT 相对尺度下（中位景深≈1）把**几乎每条样本都标成歧义**——
不报错、照常产出，只是全成了废样本。

**为什么重要**：**尺度无关的判据必须写成尺度无关的形式。**
基线充分性已改用**视差比 = 基线/景深**，实测分离度很好：
起飞悬停段 0.0115，正常航测段 0.117 / 0.240 / 0.324 / 0.412 / 0.469 —— 阈值 0.05 落在空档里。

📄 `DESIGN.md` §40.5 机制 2；`metadata_snapshot.schema.json` 的 `parallax_ratio`

## 感知可信度（C1）

### 暗光下置信度不只是变低，是**变得没用** —— 判别力损失过半

同地点同航线、亮度降到 0.25×（RTK 质心距离 10 m 的受控配对）：置信度中位降 35%，方向是对的，**模型确实知道自己看不清**。但用置信度把水面从陆面里分出来的 AUC **从 0.865 掉到 0.670**，全场四分位距从 6.91 压到 1.86。掉幅还不均匀：日间高置信的裸地腰斩（−47.8%），本就低置信的水面只掉 21.4%（它已经在地板上），所有类别向同一个低值收敛。

**为什么重要**：这推翻了下面「置信度是场景相对的」那条给出的第一条实现路径。**「按场景取分位数阈值」只能修正偏移，修不了信息量下降** —— 暗傍晚有 19.1% 的水面像素落进了本场高置信区（日间只有 8.1%），即模型在最该谨慎的地方反而变自信了。所以校准**必须按成像条件分档**，一条全局曲线会把暗场景「看着还行的 conf」错译成低错误概率。而且低照度档位上不能只靠 conf 做失效原因归因，得靠其他纯视觉机制交叉指认（估计器分歧、重投影/环路误差、扰动敏感度、语义先验）。

**副产品**：暗场景里那 19.1%「自信但不可信」的水面像素，是 C4 的**程序化负样本来源**，无需人工标注。

📄 `FINDINGS.md 附录 A` §8–§9

### 「傍晚航次」不等于「暗」，按航次名配对会配出假对照

`_Evening` 航次内部有 **4 倍亮度梯度**：17:43 亮度 0.354（比日间还亮，仍是黄金时刻），18:04 只有 0.0864。我第一次用 RTK 配到 0.1 m 的那对，日间/傍晚跑出来是**傍晚更亮 18.9%**、置信度几乎不变 —— 配对本身是错的，不是模型没反应。

**为什么重要**：这修正了此前文档里「`_Evening` 与日间同航线即构成受控成像退化对照」的说法 —— 只对**航次尾段**成立。配对条件必须**同时**约束三项：RTK 质心距离、亮度比、相机基线。少任何一项都会得出假结论。

另有一个更基础的坑：**每个航次的 world 坐标系是独立的**（原点在各自首帧），跨航次比较位置必须先换算到 RTK 绝对坐标。我曾据此误判两条完全重合的航线「无重叠」。

📄 `FINDINGS.md 附录 A` §7

### 水面的失效信号是真的，而且不用 LiDAR 就能找到

同一场景里，水面 `depth_conf` 中位 **7.21**，植被 **20.59**。
更干净的判据：**0% 的水面像素进入高置信区**，而植被有 49.3%。

**为什么重要**：**C1 的监督信号真实存在**，模型自身的置信度就是可用的水面失效探测器，不必依赖 LiDAR 残差去定位。而且这个实验**绕开了 M-008** —— 用逐像素 2D 语义标注即可，两者本就在同一像素空间。

但 LiDAR 仍然必要：置信度只说"这里不可信"，说不出"错了多少"。

📄 `FINDINGS.md 附录 A`

### 但置信度是**场景相对**的，全局阈值会错得离谱

同为植被，HKisland 中位 20.59，AMtown 只有 8.54 —— **差 2.4 倍**。

**为什么重要**：一个在 HKisland 上合理的阈值搬到 AMtown，会把**近半数植被像素**误判为不可信。这实证确认了「原始模型置信度必须校准为错误事件概率，不能直接当概率用」—— 此前那是设计原则，现在有了具体的失效数字。

**这也是 M-008 目前最实在的用途**：用 LiDAR 残差在留出数据上校准置信度。

> ⚠ 本条说的「场景相对阈值可用」已被上面「暗光下判别力损失过半」那条限定 —— 只在正常照度下成立。

📄 `FINDINGS.md 附录 A`

HKisland01 前 32 帧相机只移动了 **0.29 m**（起飞悬停段），多视角重建没有视差可用。扫描后用基线 46.6 m 的片段才有意义。

## 尺度

### 数学上可以把相对深度换算成米制 —— 但实测精度远达不到可用

**数学是对的**：多视角重建的米制模糊性只有 **1 个标量自由度**（旋转平移不改变任何两点间距离），所以一个外部约束就能锚定。UAVScenes 的 RTK 相机轨迹就是这个约束。

**但实测不成立**。同一帧用不同窗口重建再锚定，得到的米制深度差异巨大：

| 量 | 变异系数 |
|---|---:|
| 未缩放 depth | 21.0% |
| 反解尺度 | 41.8% |
| **锚定后的米制深度** | **19.5%** |

锚定后的 CV（19.5%）和锚定前（21.0%）几乎一样 —— **尺度锚定基本没起作用**。

**根因**：DA3 对同一帧的深度预测会随窗口里的其他帧而改变，这不是全局缩放差异，**一个标量补不回来**。数学前提「重建内部单位全局一致」在 DA3 上不成立。

**为什么重要**：可达精度被**重建稳定性**卡住（约 20%），不是被尺度拟合精度卡住。所以换个更好的尺度锚点没用，得先解决重建稳定性。**这个结论只针对 DA3，VGGT-Ω 未测**。

📄 `FINDINGS.md 附录 B` 「重大修正」节

### 我连续两次得出被下一个实验推翻的结论

第一次报「误差 0.5%」，第二次报「基线 ≥2 m 即可」，都被推翻。

**为什么重要**：两次都是**用被测系统自身当参考**。自洽检验只能证伪不能证实 —— 几个配置互相吻合，可能只是它们共享同一个偏差。**凡是要给出精度数字，必须有独立于被测系统的真值。**

这直接导致 **M-008（相机-LiDAR 标定文件）重新升级为必需** —— 我之前把它降级是错的。

📄 `FINDINGS.md 附录 B` §C.6

### 对齐残差小并不代表尺度可信

两帧做 Umeyama 时残差恒为 0（自由度为零，必然精确拟合），但尺度误差可达 460%。

**为什么重要**：残差是最顺手的指标，也最容易骗人。判据要看基线长度、帧数和轨迹构型，**不能看残差**。

## 专家模型

### 三个深度模型给出三个不同答案，而且都对不上 LiDAR

同一帧 UAVScenes 图像上：

| 来源 | 深度 |
|---|---|
| DA3-LARGE-1.1 | 0.57 – 1.02（归一化，非米制） |
| DA3Metric-Large | 6.97 – 23.78 m，中位 13.30 |
| MoGe-3 ViT-L | 16.74 – 22.96 m |
| LiDAR 真值 | 31.09 – 38.02 m，中位 33.13（射线距离） |

**为什么重要**：这正是"多模型不能投票产生真值"的现实例证 —— 取平均或多数决只会得到一个同样错的数。正确做法是先对齐、算残差、再校准成错误概率。

**注意这个对比本身不严谨**：LiDAR 给的是射线距离，模型给的是垂直深度，两者传感器原点和视场都不同。**严格验证需要相机-LiDAR 外参**，而 `calibration_results.py` 不在我们下载的 interval=5 档案里，只在完整版。在做完投影验证前，所有模型的 `domain_calibrated` 都保持 `false`。

### DA3Metric-Large 有米制深度，但没有置信度和相机参数

它只输出 `depth` 和 `sky` 掩码，`conf`、`extrinsics`、`intrinsics` 全是 `None`。

**为什么重要**：**过不了需要置信度的质量门禁**。它只能当单目尺度先验和天空掩码来源，不能参与位姿交叉校验。选模型时得看它到底给什么字段，不能只看任务名。

**为什么重要**：这不是配置问题，是硬冲突。但也不必强求 —— MoGe 的角色是**关键帧上的离线交叉校验**，本来就不需要和 VGGT-Ω 同进程跑。**独立环境 + 文件交换**即可。

## 附录 A：VGGT-Ω 置信度与失效区域实测（C1）


> 目的：验证 C1（感知可信度与失效归因）的监督信号是否真实存在
> 实测日期：2026-08-25
> 前提：用户提示 **VGGT-Ω 的点云重建质量并不特别好**，分析据此按「相对差异」而非「绝对值」判读

## 1. 方法：不需要相机-LiDAR 外参

UAVScenes 提供**逐像素 2D 语义标注**，与深度图在同一像素空间。
因此可以直接按语义类别切分 `depth_conf`，**绕开 M-008 的标定文件依赖**。

标注类别经 `_color` 版反查确认（`_id` 与 `_color` 同名成对）：

| 类别 ID | RGB | 语义 |
|---:|---|---|
| 4 | (173, 216, 230) 浅蓝 | **水面** |
| 13 | (107, 142, 35) 橄榄绿 | 植被 |
| 14 | (210, 180, 140) 棕褐 | 裸地 |
| 0 | (0, 0, 0) | 未标注 |

**没有假设哪个 ID 是水** —— 调色板反查是必要的一步。

## 2. 场景选择：基线不足会毁掉实验

HKisland01 的前 32 帧相机跨度仅 **0.29 m**（起飞悬停段），多视角重建无视差可用。
扫描后改用 **场景 0013，基线 46.6 m**。对照组用 **AMtown02_0000，基线 38.3 m**。

> AMtown01_0000 未被用作对照 —— 它是 `USER_ACTIONS` 待删清单 X-002 记录的坏标注残留
> （adapter v0.1.0 的 `_id`/`_color` 混淆），通道数不一致直接报错。
> 这是那条待删记录第一次实际"咬人"。

## 3. 结果：水面失效信号强且干净

HKisland01_0013，24 帧 @512：

| 类别 | 占比 | P5 | P25 | 中位 | P75 | P95 |
|---|---:|---:|---:|---:|---:|---:|
| **水面** | 23.3% | 2.96 | 4.95 | **7.21** | 9.73 | 14.03 |
| 植被 | 46.6% | 10.02 | 17.81 | **20.59** | 23.26 | 26.24 |
| 裸地 | 22.0% | 7.02 | 11.38 | 13.48 | 16.40 | 21.41 |
| 未标注 | 8.2% | 3.71 | 10.08 | 11.78 | 14.05 | 21.56 |

**水面的 P95（14.03）低于植被的中位数（20.59）** —— 两个分布基本分离。

以全场 P25/P75 为界：

| | 落入低置信区 | 落入**高**置信区 |
|---|---:|---:|
| 水面 | **76.0 %** | **0.0 %** |
| 植被 | 4.8 % | 49.3 % |

**没有任何水面像素进入高置信区。** 模型从不在水面上自信地给出深度。

### 这意味着什么

**C1 的监督信号真实存在，且不必依赖 LiDAR 残差就能定位水面失效区。**
模型自身的置信度就是一个可用的水面失效探测器。

但 **LiDAR 仍然必要** —— 置信度只说"这里不可信"，说不出"错了多少"。
量化误差、以及区分"水面/反射/无纹理"这些**不同的失效原因**，仍需独立真值。

## 4. 对照组暴露的陷阱：置信度是场景相对的

AMtown02_0000（无水面，基线 38.3 m）：

| 类别 | 占比 | 中位 conf | 落入本场 P25 以下 |
|---|---:|---:|---:|
| 植被 | 46.6% | **8.54** | 39.9 % |
| 未标注 | 27.9% | 12.17 | 15.2 % |
| 类别 19 | 6.3% | 18.02 | 0.9 % |
| 类别 3 | 6.7% | 16.94 | 1.7 % |

**同为植被，HKisland 中位 20.59，AMtown 只有 8.54 —— 差 2.4 倍。**
全场中位也差得多：HKisland 15.11 vs AMtown 10.24。

### 因此：不能用全局置信度阈值

一个在 HKisland 上合理的阈值（如"低于 10 判为不可信"），
搬到 AMtown 会把**近半数植被像素**误判为不可信。

这**实证确认了 SPEC §14.13 的要求**：原始模型置信度 MUST 校准为错误事件概率，
而不能直接当概率用。此前那是一条设计原则，现在有了具体的失效数字支撑。

**C1 的实现必须**：

1. 使用**场景相对**的阈值（分位数），或
2. 用 LiDAR 残差在留出数据上**校准**置信度到 `P(depth_error < threshold)`。

第 2 条是 §14.13 指定的正解，需要 M-008 的外参 —— 这是 M-008 目前最实在的用途。

> **⚠ 第 1 条已被 §9 的实测部分推翻。** 分位数阈值假定「高置信区 ≈ 可信」，
> 该假定在低照度场景下不成立（暗傍晚有 19.1% 的水面像素落进本场高置信区）。
> 场景相对阈值只能修正**偏移**，修不了**判别力下降**。先读 §9 再决定实现方式。

## 5. 与用户预设的关系

用户提示重建质量并不特别好。实测结果与之**一致且更具体**：

- AMtown02 全场置信度中位仅 10.24，植被有 39.9% 落在低置信区 ——
  **在没有水面的普通场景里，重建质量本身就参差**；
- 这恰恰说明按"绝对值"判读会误导，必须看**同场景内的相对差异**；
- 水面与植被的差距（7.21 vs 20.59，且高置信区占比 0% vs 49.3%）
  在这种背景噪声下**依然清晰可辨** —— 这才是信号真实的证据。

## 6. 局限

1. **各一个场景**，未覆盖 HKairport（52% 均质硬化面）；`_Evening` 航次已在 §7–§9 补测；
2. **未与 LiDAR 逐点比对** —— 只证明了"模型认为水面不可信"，
   未证明"模型在水面上的深度确实错"（虽然物理上极可能）；
3. AMtown02 中类别 1/2/3/19 的语义未反查，只按 ID 标注；
4. `process_res=512`，未测其他分辨率下信号是否稳定。

## 7. 日/暮受控对照：怎么配对才算受控

> 实测日期：2026-08-25。目标：几何真值相同、**只有成像退化**，
> 检验「模型是否知道自己看不清」。

### 7.1 三次配对，前两次都不成立

| 配对依据 | 结果 | 为什么不成立 |
|---|---|---|
| 取两航次中基线最大的各一段 | 判为"无重叠" | 按基线选段与地点无关，选到了不同区域 |
| 用各自 world 坐标算质心距离 | 判为"无重叠" | **每航次 world 系独立**，坐标不可跨航次比较 |
| **RTK 绝对坐标 + 亮度 + 基线** | 成立 | 见下 |

第二次的错误更值得记：VGGT-Ω 与 SLAM 的 world 原点定义在各自首帧，
两个航次的坐标系之间差一个未知刚体变换。**跨航次比较必须回到 RTK 绝对坐标。**
换算后两航次是同一条航线，逐点中位偏差 0.1 m，100% 落在 15 m 内。

### 7.2 「傍晚」不等于「暗」

RTK 配到 0.1 m 的那一对（`GNSS01_0041` / `Evening_0001`）跑出来是
**傍晚比日间还亮 18.9%**，置信度几乎不变（−1.4%）。

不是模型的问题，是配对的问题 —— `Evening_0001` 拍摄于 17:43，仍在黄金时刻。
扫描整个 `_Evening` 航次的亮度：

| 时刻 | 图像平均亮度 |
|---|---:|
| 17:43 | 0.3540 |
| 17:57 | 0.2696 |
| 18:01 | 0.2201 |
| **18:04** | **0.0864** |

**航次内部有 4 倍的亮度梯度。** 只有 18:00 之后的尾段是真暗。

> 这条修正了此前文档里"`_Evening` 与日间同地点同航线即构成受控成像退化对照"的说法 ——
> 该说法对**航次尾段**成立，对整个航次不成立。SPEC §40.3 C1 / §40.4 C4 已同步。

### 7.3 最终成立的配对

| | 场景 | 时刻 | 亮度 | 基线 |
|---|---|---|---:|---:|
| 日间 | `uavscenes_HKisland_GNSS01_0034` | 15:2x | 0.2845 | 52.1 m |
| 暗傍晚 | `uavscenes_HKisland_GNSS_Evening_0063` | 18:0x | 0.0712 | 64.6 m |

RTK 质心距离 **10.0 m**，亮度比 **0.25×**，两侧基线都远超视差需求。

**因此配对条件必须同时约束三项**：RTK 质心距离（航线一致）、
亮度比（退化真实存在）、基线（两侧都有可用视差）。少任何一项都会配出假对照。

## 8. 结果：置信度确实跟着掉，但掉得不均匀

24 帧 @512：

| | 日间 | 暗傍晚 | 变化 |
|---|---:|---:|---:|
| 图像平均亮度 | 0.2785 | 0.0725 | −74.0% |
| 图像对比度 | 0.2199 | 0.0848 | −61.4% |
| `depth_conf` 中位 | 11.70 | 7.60 | **−35.1%** |
| `depth_conf` P25 | 8.17 | 6.64 | −18.8% |
| `depth_conf` P75 | 15.09 | 8.50 | −43.7% |

**第一层结论：模型确实"知道自己看不清"。** 亮度降 74%，置信度中位降 35%，
方向正确。这本身对 C1 是好消息 —— 不确定性感知任务有可用的原始信号。

按语义类别拆开，画面就变了：

| 类别 | 占比 日/暮 | 日间 conf | 暗傍晚 conf | 变化 |
|---|---:|---:|---:|---:|
| unlabeled | 17% / 11% | 14.77 | 7.68 | −48.0% |
| **水面** | 62% / 69% | **9.43** | **7.42** | **−21.4%** |
| 植被 | 1% / 2% | 11.06 | 8.65 | −21.8% |
| **裸地** | 20% / 18% | **15.91** | **8.31** | **−47.8%** |

**掉幅差了一倍多。** 日间高置信的裸地腰斩，本来就低置信的水面只掉两成 ——
不是水面变可靠了，是它**已经在地板附近**，没有下降空间。
结果是所有类别向同一个低值收敛。

## 9. 关键发现：失效探测器的判别力在暗光下坍缩

C1 依赖的不是置信度的绝对值，而是它**区分可信区与失效区**的能力。
直接量化：用 conf 把水面从陆面（裸地+植被）里分出来，看 AUC。

| | 日间 | 暗傍晚 |
|---|---:|---:|
| **AUC** `P(conf_水面 < conf_陆面)` | **0.865** | **0.670** |
| 水面落入本场高置信区(>P75) | 8.1% | **19.1%** |
| 陆面落入本场高置信区(>P75) | 57.8% | 44.4% |
| 水面落入本场低置信区(<P25) | 37.5% | 27.8% |
| 陆面落入本场低置信区(<P25) | 3.3% | **17.3%** |
| 中位比 陆/水 | 1.68 | 1.12 |
| 全场 conf 四分位距 | 6.91 | 1.86 |

**AUC 0.865 → 0.670，判别力损失过半**（以 0.5 为随机基线，可用信息量从
0.365 掉到 0.170）。四分位距从 6.91 压到 1.86 —— 整个置信度分布被压扁了。

两类错误同时恶化：水面进高置信区的比例翻倍多（8.1% → 19.1%，
**这是危险方向的错误** —— 模型在水面上变得自信了）；
陆面进低置信区的比例涨了 5 倍（3.3% → 17.3%，过度保守）。

### 9.1 这对 C1 意味着什么

**置信度在暗光下不只是整体偏移，是信息量本身变少了。** 两者的处理方式完全不同：

- 若只是偏移 → 按场景重标阈值即可（§4 的结论）；
- **信息量变少 → 重标阈值救不回来**，因为可分的信息不在了。

因此 §4 给出的两条实现路径需要修正：

1. ~~场景相对阈值（分位数）~~ —— **在低照度档位失效**。分位数阈值假定
   高低置信区仍对应可信/失效，暗傍晚场景里这个假定不成立（水面 19.1% 进高置信区）；
2. **LiDAR 残差校准仍然是正解，但 MUST 按成像条件分档标定** ——
   一条全局校准曲线会把暗场景的"看起来还行的 conf"错译成低错误概率。

**而且在低照度档位上，不能只靠 conf 做失效原因归因。** §14.5 要求区分
`water` / `reflection` / `texture_poor` 等原因；AUC 0.670 说明暗光下 conf
已经分不太动"水面"这一类，原因码需要 LiDAR 残差或语义先验来补。

SPEC §14.13 已据此加入分档标定的 MUST 条款。

### 9.2 这对 C4 意味着什么

C4 的任务形态得到了实测支撑，而且**比原设想更有内容**：

原设想是"同一问题白天答准、傍晚答不确定"。实测说明还应该考察
**模型是否知道自己的不确定性估计在暗光下也不可靠** ——
这是二阶不确定性，比一阶的"我不确定"更难，也更贴近飞手的真实诉求
（"系统说它有把握，这个把握本身可信吗"）。

同时这给了 C4 一个**程序化的负样本来源**：暗傍晚场景里落入高置信区的水面像素
（19.1%），是"模型自信但实际不可信"的确定性标注，无需人工。

# ⚠️ 重大修正（2026-08-25）

**下方 §3–§5 的结论已被后续实验推翻。先读本节。**

## C.1 推翻了什么

原结论：「相对深度乘上从相机轨迹反解的尺度，即可得到米制深度，最好误差 0.5%」，
以及「基线 ≥2.0 m 即可作为米制任务的资格阈值」。

**两条都不成立。**

## C.2 系统扫描的结果

固定评估帧，用**包含该帧的不同窗口**分别重建并反解尺度，看米制深度是否收敛：

| 帧数 | 步长 | 基线 m | 对齐残差 m | 米制深度 m |
|---:|---:|---:|---:|---:|
| 4 | 1 | 3.371 | 0.3464 | 45.997 |
| 8 | 1 | 3.389 | 0.1465 | 30.273 |
| 16 | 1 | 3.390 | 0.1146 | 31.054 |
| 48 | 1 | 21.548 | 0.1529 | 31.540 |
| 16 | 3 | 18.496 | 0.1368 | 31.157 |
| **48** | **3** | **大** | — | **45.628** |

**两个长基线配置（48 帧 stride1 与 48 帧 stride3）给出 31.54 m 与 45.63 m，相差 45%。**
没有稳定的参考值，也就无从谈"误差"。

## C.3 诊断：问题不在尺度反解，在重建本身

同一评估帧在 6 种窗口配置下：

| 量 | 变异系数 CV |
|---|---:|
| 未缩放 depth 中位 | 21.0 % |
| 反解尺度 `s` | 41.8 % |
| **两者乘积（米制深度）** | **19.5 %** |

若尺度反解能有效补偿重建的内部单位，乘积的 CV 应**远小于**两个因子。
实测 19.5% ≈ 21.0%，**说明锚定几乎没有消除漂移**。

具体看：48 帧 stride1 的未缩放深度 0.6292、尺度 50.126；48 帧 stride3 的 0.4434、
尺度 102.914。原始深度差 1.42 倍、尺度差 2.05 倍，乘积仍差 1.45 倍 —— 若只是全局
尺度不同，乘积应当完全一致。

**根因**：DA3 对**同一帧**的深度预测会随窗口内其他帧而改变（参考视图选择、上下文不同），
这不是单纯的全局缩放差异，**一个标量补不回来**。

## C.4 修正后的结论

1. **数学关系仍然成立**：多视角重建的米制模糊性确实只有 1 个标量自由度。这是几何事实，不受实验影响。
2. **但前提是重建的内部单位全局一致。** 实测表明 DA3 不满足这个前提 —— 换一组输入帧，同一帧的相对深度就变了，不存在唯一的"该帧相对深度"可供缩放。
3. **因此可达精度受限于重建稳定性（本实验约 20% CV），而非尺度拟合精度。**
4. **原先报告的 0.5% 是特定窗口与 LiDAR 中位数的偶然吻合**，不可复现，不应作为依据。

## C.5 对项目的影响（覆盖 §5）

- **M-008（相机-LiDAR 标定文件）重新升级为必需。** 自洽检验已被证明不足以判定精度，
  必须用独立真值逐像素比对。我此前的降级是错的。
- **基线阈值 2.0 m 无实证支持，已从"充分条件"降为"必要不充分条件"。**
  Task Spec 的资格判定改为额外要求 `domain_calibrated: true`，
  而该标志只能由独立真值验证后置位。
- **本结论针对 DA3，不能外推到 VGGT-Ω**（点云主路径，权重待批）。
  VGGT-Ω 是多视角联合重建，稳定性可能更好，但**必须实测**，不得假定。

## C.6 方法论教训

本轮连续两次得出被下一个实验推翻的结论，原因是**用被测系统自身作参考**。
自洽检验只能证伪、不能证实：几个配置互相吻合可能只是共享同一偏差。
**凡是要给出精度数字的验证，必须有独立于被测系统的真值来源。**


## 1. 数学关系

不同深度输出形式之间的关系是明确的（对应 SPEC §14.11 的分类）：

| 深度类型 | 与真实米制深度的关系 | 未知量 | 需要几个约束 |
|---|---|---:|---:|
| `metric` | `d = d_pred` | 0 | 0（但域内偏差仍需校准） |
| `relative`（尺度不变） | `d = s · d_pred` | 1 | 1 个已知距离 |
| `affine_invariant` | `d = a · d_pred + b` | 2 | 2 个已知距离 |
| 多视角重建 | 整场景差一个**相似变换** | 7 | 但**只有尺度 s 影响米制**，其余 6 个是刚体变换 |

关键在最后一行：多视角重建的模糊性虽有 7 个自由度，但旋转与平移不改变任何两点间的距离，**只有那 1 个标量尺度会影响米制量**。所以只要有**一个**外部米制约束，就能把整个重建锚定。

## 2. 我们手上的锚点：相机轨迹

UAVScenes 每个 run 都带 RTK，且其 `T4x4` 相机中心已用 RTK 交叉验证为米制（尺度因子偏离 1.0 ≤ 0.241%）。因此：

```
s = |真实相机位移| / |重建相机位移|
```

用 Umeyama 相似变换在两条相机轨迹之间求解即可。

**这一步不需要相机-LiDAR 外参** —— 两边比的都是相机位置。这一点很重要，因为 `calibration_results.py` 不在我们下载的 interval=5 档案里。

## 3. 实测验证

对 DA3-LARGE-1.1（输出 `relative` 深度，`is_metric` 为空）：先从相机轨迹反解 `s`，再把 `s` 乘到相对深度上，与该帧 LiDAR 真值比对。

| 场景 | 相机轨迹行程 | 反解尺度 s | 对齐残差 RMS | 缩放后 depth 中位 | LiDAR 中位 | 误差 |
|---|---:|---:|---:|---:|---:|---:|
| AMtown01_0000 | 3.70 m | 37.52 | 0.141 m | 32.95 m | 33.13 m | **0.5 %** |
| AMtown01_0001 | 13.67 m | 76.23 | 0.202 m | 63.20 m | 60.17 m | **5.0 %** |
| AMtown01_0002 | **0.15 m** | 22.35 | **0.026 m** | 19.53 m | 85.94 m | **77.3 %** |

（各取前 10 帧，`process_res=504`。LiDAR 取该场景首帧点云的射线距离中位数。）

**结论成立**：相对深度乘上从相机轨迹反解的尺度后，确实落到正确的米制量级，最好情况误差 0.5%。

## 4. 边界条件：基线不足则失效

第三行是本次分析最重要的发现。

AMtown01_0002 的前 10 帧里相机几乎没移动（总行程 **0.15 m**），轨迹退化。此时：

- 尺度**无法确定** —— 误差 77.3%；
- 但**对齐残差反而是三者中最小的**（0.026 m）。

**这是个陷阱：低对齐残差不代表尺度可信。** 退化轨迹（近似静止、或纯旋转、或所有相机共线）本来就容易拟合得好，残差小只说明"这几个点能对上"，不说明尺度这个自由度被有效约束了。

判断尺度是否可信，**必须看基线长度与轨迹的几何构型，不能看残差**。

## 5. 对本项目的影响

### M-008（相机-LiDAR 标定文件）降级

原判断：没有它就无法验证米制尺度，绝对米制任务无法解锁。

**修正**：尺度恢复走相机轨迹即可，**不需要该标定文件**。它仍有价值（逐像素验证深度形状而非仅尺度），但**不再阻塞米制能力**。

### `externally_anchored` 路线被实测证实可行

SPEC §14.11 早已定义 `externally_anchored`（尺度由 RTK/GPS/LiDAR/已知基线恢复）并允许其在锚点 provenance 通过后产出米制任务。本次实测**证实了该机制在 UAVScenes 上确实可行**，并给出了具体误差量级。

这意味着：**不必依赖模型自称 metric**。DA3-LARGE-1.1 这类 relative 模型经锚定后同样可用，且比自称 metric 但未经域校准的模型更可控 —— 因为锚点来源是明确、可审计的。

### 必须新增的字段与门禁

要把这条路线变成可靠产能，需要在 metadata 与 Task Spec 中补充：

1. **场景级记录**：`camera_baseline_m`（轨迹行程与相机中心包围盒尺寸）、`scale_recovery_method`、`scale_factor`、`scale_alignment_residual_m`、锚点来源。
2. **Task Spec `eligibility` 新增基线下限**：基线过短的场景不具备出米制题的资格。
3. **门禁不得以对齐残差作为尺度可信度的唯一判据**（§4 的陷阱）。

### 建议的基线阈值

现有三个数据点给出的经验形态是「基线越长越准，但极短基线灾难性失效」：

```
0.15 m  -> 77.3 %   不可用
3.70 m  ->  0.5 %   良好
13.67 m ->  5.0 %   可接受
```

**建议初版取 `camera_baseline_m >= 2.0` 作为米制任务的资格下限**，并把 `scale_factor` 与基线一并存入 metadata 供下游复核。

但必须说明：**三个点不足以定阈值**，2.0 m 是保守取值而非实测拐点。正式确定前应做系统扫描（固定场景、改变帧数与采样间隔，画出「基线 vs 尺度误差」曲线）。

## 6. 本分析的局限

1. **LiDAR 对比不严格**：LiDAR 给的是射线距离，模型给的是垂直深度，传感器原点与视场也不同。因此绝对误差数字是量级参考，不是精确测量。跨场景的**相对比较**仍然有效（同一偏差作用于所有行）。
2. **仅测了 DA3-LARGE-1.1**，未覆盖 VGGT-Ω（权重待批）与 MoGe-3。
3. **仅测了 AMtown01 一个 run**，未覆盖其他地点与时段。
4. AMtown01_0001 的 5.0% 误差偏大，原因未查清 —— 可能是该窗口地形起伏更大导致中位数不可比，也可能是尺度估计本身的误差。需要逐像素比对（即 M-008 的用途）才能区分。

1. **不能把这批点云当作首批闭环的几何输入。** 缺置信度与相机参数，过不了 G1/G2；且为 relative 尺度，与首版"强制 metric"政策冲突。
2. **本 Pipeline 必须保存 VGGT-Ω 的完整输出**，而不只是导出一个可视化 `.ply`。至少需要：depth、depth confidence、相机内外参、坐标系与尺度声明、checkpoint hash。
3. **UAVScenes 的多视角 + RTK 是关键差异点。** 它能提供本批语料缺失的两样东西：真实多视角基线（而非单视角反投影）与米制锚点（已实测尺度因子偏离 1.0 不超过 0.241%）。
4. **深度起伏小是航拍固有难点**，需在任务设计时正面处理：优先选取有高差的场景（建筑、杆塔、植被冠层），并在 Task Spec 的 `eligibility` 中加入深度起伏下限。
