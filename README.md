# 低空无人机 2D → 3D 数据生成项目

> 从**只有 2D 图像/视频**的低空数据集出发，用 3D 专家模型提取三维特征，
> 生成**可验证的三维场景理解训练数据**。
>
> **本文档是你的追踪入口** —— 回答「还有什么要做、做到哪了」。
> 想知道「具体改了什么」看 `docs/CHANGELOG.md`；想看设计细节看 `docs/DESIGN.md`。
>
> 当前阶段：**一、四层规格就绪，二层提取链路建设中** ｜ 主规格 `docs/DESIGN.md` v0.4.0 ｜ 更新于 2026-08-25

## 🎯 要交付什么

低空 3D 点云训练数据此前基本不存在。**首要交付物不是语料，而是方向。**

| 优先级 | 交付物 |
|---|---|
| **1** | **值得做的下游任务类型** —— 即使我们的数据在该任务上质量不高，任务本身指明方向 |
| **2** | **能力缺口的论证** —— 缺的能力是什么、为何现有数据供不上、为何该任务能训到它 |
| **3** | **「好数据」的判据** —— 给后来做数据的人的优化目标 |
| **4** | **可移植的生成方法** —— 纯视觉管线 + 实测误差刻画 |
| 5 | 语料本身 —— 存在性证明与基线，**不是终点** |

### 项目定位（诚实版）

不引入新数据集、不做人工标注、不训练新的三维基础模型。
本质是**把一批各有所长的三维专家模型的能力蒸馏进一个 VLM —— 博采百家之长**。

不可替代性从低到高三层：

| 层 | 做法 | 上限 |
|---|---|---|
| 1 | 单教师蒸馏（VGGT-Ω 几何能力 → VLM） | 不超过该教师 |
| 2 | 多教师融合（几何/语义/分割/跟踪各取所长） | 各教师能力的**并集** |
| **3** | **集成结构产生的新信号**（教师**分歧** → 可靠性） | **超出任何单个教师的输出接口** |

**C1 之所以是旗舰，因为它在第三层** —— 没有哪个专家模型会告诉你「我这里不可靠」。

## 🧭 设计要点

### 推导链：设计时从右往左，执行时从左往右

```
        执行方向（运行时）→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→

 数据源      3D 专家模型提取        结构化 3D metadata      任务编译          下游任务数据
 (2D)   →   VGGT-Ω/MoGe/DA3/  →  点云·位姿·深度·置信度  →  隐藏 target +  →  训练集/
            分割/光流/跟踪         ·法向·平面·语义·关联      evidence+checker    Benchmark

←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←  推导方向（设计时）
```

**先定要什么任务，再倒推需要什么 metadata、用哪些模型、数据源要满足什么。**
反过来做（先看能提取什么再想能出什么题）会产出一堆「能生成但没价值」的任务。

配套的**反向证成规则**：每个提取阶段、metadata 字段、专家模型、门禁，
都必须能指名它服务的下游能力，指不出来就删（`DESIGN.md` §0.3 有证成表）。

### 三条硬约束

- **铁律 14（纯视觉）**：target 必须能从数据集自身的图像/视频 + 模型推出。
  LiDAR/RTK 只用于**验证与标定**（Release D），不得作为生产前提 ——
  否则方法只对极少数特殊数据集适用。**提取结果允许不准**，靠五条机制应对
  （测量优于观点、序数/角度优于米制、一致性做筛子、失效即标签、尺度分档）。
- **铁律 5（判据是「3D 增益」不是「2D 做不到」）**：我们的 3D metadata 是专家模型
  从同一批 2D 图像提取的，信息论上不存在 2D 绝对答不出的任务。改为实测
  `lift = score(2D+metadata) − score(2D only)` 显著 > 0 **且打乱 metadata 后增益消失**。
  口子放宽但没放空 —— 从「断言不可解」变成「拿出数字」。
- **每个任务必须有六问论证**（`DESIGN.md` §52：能力缺口 / 为何能训到 / **当前上限** /
  **好数据特征** / 衡量指标 / **3D 增益**）。**缺论证的任务不进 Release。**
  当前上限必须诚实写明 —— 写清做不到什么，正是「指方向」的一部分。

### 四类目标能力（Release B，本项目核心贡献）

| 优先级 | 能力 | 不可替代之处 | 当前实测 |
|---|---|---|---|
| **C1** | **感知可信度与失效归因** | 失效标注由纯视觉可复算测量产出（重投影/环路误差、估计器分歧、扰动漂移）。**对别的能力「提取的 3D 是错的」是噪声，对 C1 教师犯错就是数据** | ✅ 水面/陆面判别 AUC **0.865**（未用 LiDAR） |
| **C2** | **安全降落区评估** | 垂直下视正是评估降落区的视角。**坡度是角度、粗糙度可取比值，缩放下不变，无需尺度锚**。核心是「平坦 ≠ 可降落」——水面平、车顶平、人群上方也平 | ⬜ 未测。软肋：弱纹理地面上视觉几何最差，而那恰是最需要判断的地方 |
| **C3** | **地形与高度推理（分档）** | Nadir 图像几乎不提供深度线索，同色屋顶与地面外观相近。**C3-a 序数/比值**（默认，对深度误差稳健）；**C3-b 绝对米制**（需 T3 的 GPS/EXIF 锚） | ⬜ 未测。C3-b 是本项目**唯一**真正 2D 不可解的一类（信息不在像素里） |
| **C4** | **成像退化鲁棒与二阶不确定性** | **改用合成退化**，任何数据集可做，不需要重复航次。最被忽视的一层：模型的**不确定性估计本身**在退化下失准 | ✅ 判别力 AUC 0.865 → **0.670**，水面进高置信区 8.1% → **19.1%**（**最该谨慎时反而更自信**） |

完整论证（含「好数据的特征」）见 `DESIGN.md` §52。

### Release 顺序

| | 内容 | 说明 |
|---|---|---|
| **A** | 可移植基础监督 | 3D 分割、Grounding、metric/situated VQA、跨视角对应、可见性 |
| **B** | **航拍差异化能力** | C1 → C2 → C3 → C4。**全部走纯视觉** |
| **C** | 语言与长时程 | Caption、Dialogue、Scene Graph、空间反事实 |
| **D** | **验证与标定报告**（非训练数据） | 在 UAVScenes 上用 LiDAR 测**一次**：纯视觉管线错多少、置信度准不准、合成退化像不像真的。**这是「方法可移植」的证据** |
| **E** | 导航类能力 backlog | 解锁条件是 R-37（引入前视/侧视数据集） |

### 环境约束

- 两个隔离 conda 环境：`nyp-3dpipe`（numpy<2，VGGT-Ω/DA3）与 `nyp-moge`（numpy≥2）——
  **二者无法合并**，是硬依赖冲突。调用时必须带 `PYTHONNOUSERSITE=1`，
  否则 `~/.local` 的 35 个包会渗进来。
- **禁止改动共享 base 环境** `/opt/conda/envs/ptca`（`CLAUDE.md` 规则 3）。
- **占卡程序必须保持挂载** —— 服务器连续 2 小时未用显卡会被释放（`CLAUDE.md` 规则 2）。
- 本地 `data/` 只有 QA 标注 JSON，**无图像/视频/点云**，不能作为重建输入。

### 与 3D-GRPO 的关系

**本 Pipeline 的最终产物是一对交付物**：点云 + 该点云对应的下游任务标注。只生成点云不算完成。

同级 `3D-GRPO` 是**下游的训练框架**：用产出的点云 + 任务标注做 SFT，
再用 GRPO 训练自有点云理解模型。**当前与数据生成解耦**，无需为其调整排期。
因此三类 adapter 中 `pointcloud_native` 有明确消费方，优先级不低于 `qwen_2d_metadata` ——
这不改变铁律 2/3，Qwen 仍只读 2D + metadata。
